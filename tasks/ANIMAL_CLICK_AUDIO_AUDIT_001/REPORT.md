# 动物点击音效接口核查

2026-10-27 · DEV_INTEGRATION · 检查基线main `3c058e6`

结论：**已有可复用的动物点击识别入口，但没有专门的声音配置、事件接口、播放模块或音频导出支持。** 不能称为“已经预留好、放入音频就能响”。当前PNG是静态图像资源，声音需要独立音频文件及程序绑定。本轮按用户要求检查接口，未擅自实现新音效玩法。

已核查运行代码、动物元数据、资源目录与导出器：

| 层次 | 当前实际情况 |
|---|---|
| 动物识别 | `chapterAnimals`按shape_id映射完整动物；实例有piece_id、shape_id与art_asset_id，可据此选择动物专属声音 |
| 输入入口 | `game.js`左键pointerdown调用locate识别动物，然后建立held整体拾取状态；可在成功识别后触发一次音效 |
| 专用音效钩子 | 没有独立onAnimalClick回调或向音效消费者发送的动物点击事件，当前入口是游戏内部事件处理 |
| 素材声音字段 | 11种运行配置均没有clickSound/sound/audio等声音字段 |
| 播放模块 | chapter运行目录没有Audio、AudioContext、play()或audio标签相关实现 |
| 音频文件 | assets目录未发现mp3、ogg、wav、m4a、aac、flac或webm音频资源 |
| HTML5导出 | 现有导出器处理PNG和脚本/样式依赖，没有音频资源映射、音频闭环校验或播放回归 |

后续实现可以复用当前程序：为每个动物素材登记独立clickSound，在成功左键按下动物的入口播放一次；同种动物的多个实例复用同一配置。拖拽移动不重复播放，右键旋转也不自动当作左键点击。增加共用播放模块处理音量、静音、连点叠加/冷却与缺失文件失败；随后补充音频导出、实际点击播放和拖拽回归。不要将音频文件名写入关卡碰撞数据，也不需要修改动物PNG或重做拼图引擎。

上述为可落地的接入位置说明，**尚未实现或测试声音播放**。当前玩法仍然无点击音效。用户同条消息的“试玩成功”已单独写入第三批运行验收记录，不扩大为未实现音频功能的批准。
